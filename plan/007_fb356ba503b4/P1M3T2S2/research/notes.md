## Key architectural difference vs Scoop S2 / Homebrew S2 (the structural twins)
- Scoop/Homebrew S2 = "PURE local file update — does NOT push" (regex-patch local manifest; CI does
  the deploy-key git push to a repo WE own: `dabstractor/scoop-qmkonnect`, `dabstractor/homebrew-qmkonnect`).
- Winget S2 = the target is `microsoft/winget-pkgs` (EXTERNAL repo we do NOT own). Publication is a
  **PR**, opened atomically by `wingetcreate update --submit --token` (fork → branch → PR). So
  `submit.ps1` actually OPENS THE PR (it is not a pure local patcher). It does NOT regex-patch the
  local S1 YAML — `wingetcreate update` fetches the EXISTING winget-pkgs manifest and updates it.
  The local S1 YAML is only the template for the one-time manual `wingetcreate new`.
- Hence NO separate bucket/tap-style README (unlike Scoop `bucket-README.md` / Homebrew `tap-README.md`).
  Deliverable docs = ONE section appended to S1's `packaging/winget/README.md`.

## wingetcreate CLI — confirmed flags (long forms are High-confidence)
Sources: microsoft/winget-create discussion #190, MS Learn, techcommunity blog, ImageMagick automation.
- `wingetcreate update <PackageIdentifier>` (positional id)
- `--urls  "<URL>|<SHA256>"` / `-u` — pipe-delimited URL+hash. Hash OPTIONAL (wingetcreate computes
  if omitted), but the contract wants us to compute+pass it.
- `--version <ver>` / `-v` — bare version (no leading v).
- `--token  <PAT>` / `-t` — classic GitHub PAT, `public_repo` scope.
- `--submit` — auto-open PR to microsoft/winget-pkgs (forks under token owner, PRs to microsoft:main).
- `--out <dir>` / `-o` — generate manifest YAML locally WITHOUT submitting (the "review" mode).
- `wingetcreate new <installerURL> --token <PAT> --submit` — FIRST submission (interactive; prompts for
  metadata). `update`/actions only work AFTER the package exists in winget-pkgs.
- NO `--title`/`--notes` on `update` (PR title is auto-generated by the winget-pkgs bot convention).

### PowerShell gotchas (highest stakes)
1. **[HIGH] The `|` in `URL|HASH` is the PowerShell pipeline operator if bare.** Fix: build the
   wingetcreate args as an ARRAY and SPLAT it (`& wingetcreate @wcArgs`). Each array element is one
   argv token, so the `|` inside the `URL|HASH` string never reaches the PowerShell parser. Do NOT
   build a command string + `Invoke-Expression` (re-parse breaks on the pipe).
2. **[HIGH] Never echo the token.** The script's own log line must redact `--token` to `***`; the real
   token travels only inside the splatted argv to the wingetcreate process.
3. Prefer LONG flag forms (`--urls`/`--version`/`--token`/`--submit`/`--out`) — sidesteps short-form
   ambiguity across wingetcreate builds.

## vedantmgoyal9/winget-releaser@v2 — the ALTERNATIVE (documented in README; CI = P1.M5.T2.S1)
Source of truth: `action.yml` read from the repo (vedantmgoyal9/winget-releaser).
- Current major: **@v2** (the documented/maintained wrapper). Pin a major, NOT @latest.
- Under the hood it uses **Komac** (`cargo binstall komac`), NOT wingetcreate → cross-platform
  → runs on **ubuntu-latest** (Option B), whereas raw wingetcreate CLI runs on **windows-latest** (Option A).
- Exact `with:` inputs (from action.yml):
  - `identifier` (required) — `dabstractor.QMKonnect`
  - `version` (OPTIONAL) — **GOTCHA**: if OMITTED, defaults to release tag with leading `v` STRIPPED
    (`$ReleaseInfo.tag_name -replace '^v'`); if PROVIDED, used VERBATIM (NOT stripped). So to get a bare
    `0.2.8` from a `v0.2.8` tag you must either OMIT `version` or pass an already-stripped value. NEVER
    pass `version: ${{ github.event.release.tag_name }}` (that yields `v0.2.8` verbatim → winget rejects).
  - `installers-regex` (required, default `'.(exe|msi|msix|appx)(bundle){0,1}$'`) — use
    `'QMKonnect-.*-windows-x64\.exe$'` to target only our asset.
  - `token` (required) — classic PAT, `public_repo` (NOT default GITHUB_TOKEN).
  - `release-repository` (required, default `${{ github.event.repository.name }}`) — set `dabstractor/qmkonnect`.
  - `release-tag` (default `${{ github.event.release.tag_name || github.ref_name }}`).
  - `fork-user` (default `${{ github.repository_owner }}` = `dabstractor`) — auto-fork to dabstractor/winget-pkgs.
  - `max-versions-to-keep` (default `'0'` = keep all).
- Pre-flight: the action checks the package EXISTS in winget-pkgs; if not, errors:
  *"Package … does not exist in the winget-pkgs repository. Please add at least one version of the
  package before using this action."* → confirms the manual-first requirement.

## PAT requirement (confirmed)

- The default `${{ secrets.GITHUB_TOKEN }}` is scoped to dabstractor/qmkonnect ONLY and CANNOT fork

- Create at https://github.com/settings/tokens (classic) → check `public_repo`.

## Validation strategy on the Linux dev box
- `pwsh -NoProfile -Command "[ScriptBlock]::Create((Get-Content -Raw submit.ps1)) | Out-Null"` → parse check.
- **MOCK test** (the gold check — proves command construction WITHOUT wingetcreate installed):
  create a temp bin dir with a `wingetcreate` shim that appends `"$@"` to a capture file, prepend to PATH,
  run `pwsh -File submit.ps1 -Version 9.9.9 -Sha256 <h>` (review) and `... -Submit -Token testtok` (submit);
  assert the captured argv equals the expected `update dabstractor.QMKonnect --urls "<url>|<h>" --version 9.9.9
  [--out <dir> | --token testtok --submit]` AND that `testtok` does NOT appear in the script's own stdout
  (proves the token-redaction in the log line). The `|` survives as ONE argv token (proves the splat fix).
