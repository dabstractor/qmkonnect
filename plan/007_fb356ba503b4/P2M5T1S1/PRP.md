## User Persona (if applicable)

**Target User**: Linux users on a genuine X11 session (lightdm/Xorg login, a
standalone WM like i3/bspwm/Openbox/Awesome, or the X11 DE tail) — the
population for which no higher-priority Wayland/GNOME/Hyprland/AT-SPI backend
applies. Also: anyone building the **minimal trayless service** via
`--no-default-features`, which collapses to X11-only.

**Use Case**: On a pure-X11 box, window focus changes switch the QMK layer via
the retained 500 ms `xprop` poll. On a Wayland box, X11 is **never** picked
(XWayland focus is unreliable for native windows) — a higher-priority backend
wins or the app enters the no-backend fallback posture.

**User Journey**: log into an X11 session → launch `qmkonnect` → verbose log
shows `select_linux_backend: probing 'x11'… → 'x11' available, selected` → focus
changes emit `[Nms] … Class: '<class>', Title: '<title>'` → QMK layer switches.

**Pain Points Addressed**: (1) a single binary works on the X11 DE tail without a
rebuild (X11 is always compiled in); (2) no "picked X11 on GNOME-Wayland and
silently reported wrong windows" trap (the Wayland gate).

## Why

- **The target state is ALREADY PRESENT.** This is the central, non-obvious fact
  an implementing agent must internalize before doing anything. The X11-unconditional
  + Wayland-gate work landed in two earlier, COMPLETE tasks (P2.M1.T1.S1 +
  P2.M1.T2.S2). An agent that "re-implements" risks **breaking** correct code
  (e.g. re-introducing a feature gate, duplicating the Wayland check in
  `linux.rs`, or touching the parallel-owned `mod gnome;`). The PRP therefore
  biases toward **verify, confirm, leave-as-is**.
- **§10 is the documented lowest tier of the F16 backend matrix.** It exists so
  the X11 DE tail is covered with zero build flags, while being explicitly
  never-selected under Wayland. This task is the acceptance gate that the matrix's
  lowest rung is wired exactly as specced.
- **Invariant 11 is the headline correctness property.** XWayland sets
  `$DISPLAY`, so a naive "DISPLAY set ⇒ X11" gate would silently pick X11 under
  every Wayland compositor and report the wrong focused window. The gate lives in
  exactly one place — `x11::probe_available` — and `select_linux_backend` reaches
  it via the candidate list. The 7 `select_tests` lock it.
- **The verification is hermetic + reproducible on the dev box.** None of the
  gates need a live X server: `--no-default-features` isolates X11, and the
  select_tests manipulate process-global env vars (single-threaded) to exercise
  DISPLAY/WAYLAND_DISPLAY/xprop combinations without a display.

## What

A verified X11 backend selection where:
1. **X11 compiles unconditionally** — `#![cfg(target_os = "linux")]` file gate
   (no feature flag); `mod x11;` ungated in `mod.rs`; candidate-list row + the
   `"x11"` `construct_backend` arm both ungated; no `x11` Cargo feature exists.
2. **The selection probe gates on `$WAYLAND_DISPLAY` unset** — inside
   `x11::probe_available`, in addition to `$DISPLAY` set + `xprop` on PATH.
3. **500 ms poll + WM_CLASS-class parse unchanged** — `Duration::from_millis(500)`
   worker poll; `parse_wm_class` prefers class (2nd field), falls back to instance.
4. **`list_foreground_windows()` unaffected** — the `mod.rs` cfg ladder needs no
   X11 arm (X11 is a fallback; tray window-info was never wired for it); the
   catch-all `Vec::new()` compiles under every feature combination.
5. **Docs note present** — `spec/PLATFORMS.md` §10 (+ §6 priority row #5) states
   "lowest-priority, compiled in on every Linux build, never under Wayland".

// ── The single source of truth for the gate (src/platforms/x11.rs) ───────────
//   VERIFIED PRESENT. Do not edit unless Task 2 fails.
pub(crate) fn probe_available(_verbose: bool) -> Result<(), String> {
    let display = std::env::var("DISPLAY").ok().filter(|s| !s.is_empty());
    if display.is_none() {
        return Err("$DISPLAY is not set".into());
    }
    // Invariant 11 (ARCHITECTURE.md §10): X11 is NEVER selected under Wayland.
    if std::env::var("WAYLAND_DISPLAY").ok().filter(|s| !s.is_empty()).is_some() {
        return Err(
            "Wayland session ($WAYLAND_DISPLAY set) — X11 is never selected under a Wayland \
             compositor (XWayland focus is unreliable for native windows; PLATFORMS.md §6/§10)"
                .into(),
        );
    }
    match std::process::Command::new("which").arg("xprop")
        .stdout(std::process::Stdio::null()).stderr(std::process::Stdio::null()).status()
    {
        Ok(s) if s.success() => Ok(()),
        Ok(_) => Err("`xprop` not found on PATH (install xorg-xprop)".into()),
        Err(_) => Err("`which` not available to verify `xprop`".into()),
    }
}
